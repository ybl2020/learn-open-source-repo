# Learning Evaluation Rubric

Evaluate at module boundaries and at the end of the repository course.

## Level 1: Explain / 能说清楚

The learner can explain the technique in plain language, state the problem it solves, and distinguish it from neighboring concepts.

## Level 2: Locate / 能找到

The learner can identify the entry point, core implementation, important data structures, and where output is produced in the repository.

## Level 3: Modify / 能修改

The learner can change one meaningful input or parameter and predict the likely effect without copying an answer.

## Level 4: Verify / 能验证

The learner can run the modified example, interpret intermediate and final output, identify whether the result matches expectations, and diagnose a discrepancy.

## Level 5: Transfer / 能迁移

The learner can design where the technique belongs in a real or hypothetical project, explain trade-offs, and implement or specify a minimal integration.

## Checkpoint Format

Use a compact checkpoint:

```text
Concept: What problem does this solve?
Code: Which function or module implements it?
Prediction: What changes when parameter X changes?
Evidence: Which runtime result supports the conclusion?
Transfer: Where would this appear in the target project?
```

## Completion Criteria

Do not call the repository learned merely because every example ran. Completion requires:

- a coherent architecture and runtime-flow explanation;
- successful representative examples;
- at least one learner-driven modification per major module;
- documented limitations or failed cases;
- a transfer design for a real or persistent hypothetical project;
- truthful summary language suitable for review or interviews.
